# /contracts · 契约（唯一权威）

> **这里是全仓数据形状与接口的唯一权威**（宪法 `AGENTS.md` §1/§3）。前端、后端、未来的对话 agent 都吃这一份。
> **状态：✅ v1 已冻结（2026-06-10 指挥人审定）。** 此后改动走宪法 §6：破坏性变更升版本，纯新增可选字段走轻流程；**改了模型必须重新生成 TS**（`python contracts/generate_ts.py`，校验用 `--check`）。

## 规矩（先读）

1. **唯一权威**：跨模块共享的数据形状只在这里定义。`01_系统蓝图/.../03_契约与工单` 只放设计说明与指针，**不保存字段拷贝**。
2. **改契约 = 动共享接缝**：先停下，单独开说明卡 / 小提交，经指挥人确认（宪法 §6）；**破坏性变更升版本**（`v1` 保留 → 加 `v2`），纯新增可选字段走轻流程。
3. **TS 类型是生成物**：由脚本从本目录 Pydantic 模型生成到前端 `src/contracts/`（**待建**，见下方"待办"），**禁止手改**；改了模型必须重新生成（配新鲜度检查）。
4. **来源映射就住在字段上**：每个字段的 `description` 标注它的来源——`02/<目录>《列名》`（真实数据表头）、`01§x`（业务语义节号）、`配置`（源表没有、需人工补充维护）、`引擎`（计算产物）。改 `02_项目数据/*/表头.md` 的人，必须同步检查这里受影响的字段（宪法 §2 数据规矩）。

## 关键导入规则（名字 → id、撞号根治）

- **模板活动 id**：用 `02/01_活动定义《活动ID》`（如 `3.1`），**模板内唯一**；`02/02_活动依赖` 已按 id 连边（`前置活动ID`/`后继活动ID`），直接用。
- **`02/04_计划基线` 的 SS/SF/FS/FF 列实为「活动名文本」**（T-001 实证修正，原以为按《序号》）→ 导入器按活动名解析到对应《序号》作为活动 id，兼容全角/半角括号与少量确定性别名（如机房改造三子行 → `2.3`）；解析不到 → 导入报错（含行号），不许静默丢。
- **实例 id**：活动按作用域实例化后 `instance_id = <作用域对象id>/<活动ID>`（如 `B2DH401-POD01/3.1`；项目级用 `project/<活动ID>`）——同一模板活动复制到多个 PoD 不再撞号。
- **SLA 解析**：`02/01《SLA》` 形如 `3天` → 解析为整数天；解析失败 → 导入报错。
- **PoD id = 管理单元全称**（如 `B2DH401-POD01`，来源 `02/05《PoD名称》` 与 `02/06《管理单元》`，两表同语）。
- **阶段分组行跳过**：`02/04《序号》` 形如 `阶段N` 的行是分组行、不是活动（其 作用域/SLA形态 为空属正常）。
- **《SLA形态》= `—`**：机房准备 / 到货类活动——**不读 SLA**，工期由外部日期锚定（机房就位三段 / 到货日）。
- **机房改造实施的三个子行**（可布线 / 可装服务器 / 可通液，无序号）映射 `Room` 的三段 ready 字段（cabling / install / liquid）。
- **工时文本四式**（解析自 02/04《标准工时》/《极限工时》单元格，2026-06-10 实读核定）：
  ① `总量/天数`：`2688根/12天` → 日速率 224/天；② `速率/天`：`48柜/天`、`30台/天`；
  ③ **多子型号分行**：`盒式：40台/天` + `框式：16台/天` → 拆成多条 `WorkloadRule`；
  ④ **规模分档多行**：`千卡以下，5天 / 千卡至万卡，11天 / 万卡以上，18天` → 按 `project.project_scale` 取档落 `standard/minimum_sla_days`（**换档需重导入**）。
  解析失败一律报错可见，不静默吞。

## 后端怎么 import

仓根加入 `PYTHONPATH`（后端启动脚本里做），然后 `from contracts.inputs import Activity`。`04 后端/` 的应用代码**不得**自定义同名形状。
