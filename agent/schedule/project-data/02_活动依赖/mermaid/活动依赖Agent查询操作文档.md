# 活动依赖 Agent 查询操作文档

## 1. 目录理解

1. 进入目录：

   ```text
   D:\SourceCode\DeliveryCorps\aida-delivery\02_项目数据\02_活动依赖\mermaid
   ```

2. 只使用本目录下的 `.mmd` 和 `.md` 文件作为活动依赖查询依据。

3. 优先读取以下文件：

   ```text
   活动依赖映射0609.md
   ```

4. 按用途选择 Mermaid 文件：

   | 文件 | 用途 |
   | --- | --- |
   | `00_活动总览-按一级活动.mmd` | 全量查询、审计、跨场景依赖确认 |
   | `01_工勘建模仿真LLD设计.mmd` | 工勘、建模仿真、LLD 设计链路 |
   | `02_智算子系统部署调测.mmd` | 智算服务器部署调测链路 |
   | `03_总线设备与灵衢网络部署.mmd` | 总线设备、灵衢网络部署链路 |
   | `04_通算服务器部署调测.mmd` | 通算服务器部署调测链路 |
   | `05_存储子系统部署调测.mmd` | 存储子系统部署调测链路 |
   | `06_网络子系统部署调测.mmd` | 网络子系统部署调测链路 |
   | `07_集群测试与验收交付.mmd` | 集群调测、验收、移交链路 |

5. 默认可信口径：

   ```text
   正式活动：71 个
   唯一依赖边：110 条
   缺失活动：0 个
   缺失依赖边：0 条
   额外依赖边：0 条
   ```

6. 必须识别 2 个“被依赖但未定义为正式活动”的节点：

   ```text
   远程视频辅助
   计算子系统验证-通算服务器
   ```

7. 遇到上述 2 个节点时，只能标记为：

   ```text
   基线依赖引用，未定义活动行
   ```

8. 不要为未定义活动行补充或推断：

   ```text
   工时
   SLA
   上游依赖
   所属一级活动
   是否可开工
   ```

## 2. 查询前准备

1. 读取 `活动依赖映射0609.md`。

2. 确认查询活动是否在“逐活动映射表”中。

3. 如果用户输入的是简称、错别字、口语化名称，先做活动名称匹配。

4. 匹配优先级：

   ```text
   完整活动名
   序号 + 活动名
   二级活动名
   场景文件中的节点名
   映射文档中的近似名称
   ```

5. 如果只命中 1 个活动，直接查询。

6. 如果命中多个活动，先输出候选项，让用户确认。

7. 如果未命中活动，输出：

   ```text
   未在当前活动依赖基线中找到该活动。
   ```

8. 未命中时继续给出最接近的 3-5 个候选活动。

## 3. 活动名称匹配步骤

1. 从用户问题中提取核心关键词。

2. 在 `活动依赖映射0609.md` 中搜索关键词。

3. 如果映射表命中，记录：

   ```text
   行号
   序号
   一级活动
   二级活动
   颗粒度/工时/SLA
   表格入依赖
   Mermaid 节点位置
   Mermaid 依赖边位置
   ```

4. 如果映射表未命中，搜索 `00_活动总览-按一级活动.mmd`。

5. 如果总览图未命中，搜索 `01`-`07` 场景图。

6. 如果命中的是 `远程视频辅助` 或 `计算子系统验证-通算服务器`，立即标记为未定义活动行。

7. 不允许把未定义活动行当作正式活动。

## 4. 查询直接前置依赖

1. 确认目标活动标准名称。

2. 打开目标活动所在 Mermaid 文件。

3. 查找所有指向目标活动的边：

   ```text
   上游活动 -->|FS| 目标活动
   上游活动 -.->|SS| 目标活动
   上游活动 ==>|FF| 目标活动
   上游活动 --x|SF| 目标活动
   ```

4. 如果场景文件中的依赖不完整，回到 `00_活动总览-按一级活动.mmd` 确认。

5. 输出每条前置依赖：

   ```text
   上游活动名称
   依赖类型
   是否正式活动
   所在文件
   ```

6. 如果没有入边，输出：

   ```text
   当前基线中未配置该活动的前置依赖。
   ```

## 5. 查询全量前置依赖

1. 先查询目标活动的直接前置依赖。

2. 对每个正式前置活动继续查询其前置依赖。

3. 遇到未定义活动行时停止向上展开。

4. 遇到重复活动时停止重复展开。

5. 按层级输出：

   ```text
   L1：直接前置
   L2：前置的前置
   L3：继续上游
   ```

6. 对每条依赖保留类型：

   ```text
   FS / SS / FF / SF
   ```

7. 不要把不同依赖类型合并成普通先后关系。

## 6. 查询直接后续影响

1. 确认目标活动标准名称。

2. 打开目标活动所在 Mermaid 文件。

3. 查找所有从目标活动发出的边：

   ```text
   目标活动 -->|FS| 下游活动
   目标活动 -.->|SS| 下游活动
   目标活动 ==>|FF| 下游活动
   目标活动 --x|SF| 下游活动
   ```

4. 如果场景文件中的下游不完整，回到 `00_活动总览-按一级活动.mmd` 确认。

5. 输出每条后续影响：

   ```text
   下游活动名称
   依赖类型
   是否正式活动
   所在文件
   ```

6. 如果没有出边，输出：

   ```text
   当前基线中未配置该活动的后续依赖。
   ```

## 7. 查询全量后续影响

1. 先查询目标活动的直接下游。

2. 对每个正式下游活动继续查询其下游。

3. 遇到重复活动时停止重复展开。

4. 按层级输出：

   ```text
   L1：直接影响
   L2：间接影响
   L3：继续下游
   ```

5. 如果下游最终通向验收或移交，明确标记：

   ```text
   影响验收交付链路
   ```

## 8. 判断活动能否开始

1. 查询目标活动的直接前置依赖。

2. 只对正式活动判断完成状态。

3. 如果没有项目执行状态数据，只输出开工条件，不输出“可以开始”。

4. 如果有项目执行状态数据，逐项检查前置活动状态。

5. 判断规则：

   | 依赖类型 | 开工判断 |
   | --- | --- |
   | FS | 上游活动完成后，目标活动才能开始 |
   | SS | 上游活动开始后，目标活动才能开始 |
   | FF | 不直接限制目标活动开始，限制目标活动完成 |
   | SF | 当前基线无实际内容，按预留类型处理 |

6. 输出格式：

   ```text
   活动：xxx
   开工所需前置：
   1. xxx，FS，需完成
   2. xxx，SS，需开始
   不能判断项：
   - xxx，基线依赖引用，未定义活动行
   结论：
   - 无状态数据：只能给出开工条件
   - 有状态数据：给出可开工/不可开工
   ```

## 9. 查询两个活动之间的路径

1. 标准化起点活动名称。

2. 标准化终点活动名称。

3. 从起点活动开始查询下游。

4. 逐层展开，直到：

   ```text
   找到终点活动
   已无下游活动
   遇到重复活动
   ```

5. 如果找到路径，输出完整链路。

6. 如果存在多条路径，按路径长度从短到长输出。

7. 如果找不到路径，输出：

   ```text
   当前基线中未找到二者之间的依赖路径。
   ```

## 10. 查询场景链路

1. 判断用户查询属于哪个场景：

   | 关键词 | 场景文件 |
   | --- | --- |
   | 工勘、建模、LLD、低阶设计 | `01_工勘建模仿真LLD设计.mmd` |
   | 智算、液冷、计算柜 | `02_智算子系统部署调测.mmd` |
   | 总线、灵衢 | `03_总线设备与灵衢网络部署.mmd` |
   | 通算 | `04_通算服务器部署调测.mmd` |
   | 存储 | `05_存储子系统部署调测.mmd` |
   | 网络 | `06_网络子系统部署调测.mmd` |
   | 集群、验收、移交、通信测试 | `07_集群测试与验收交付.mmd` |

2. 打开对应场景文件。

3. 提取场景内所有节点。

4. 提取场景内所有依赖边。

5. 如果需要跨场景确认，回到 `00_活动总览-按一级活动.mmd`。

6. 输出：

   ```text
   场景名称
   关键活动
   主链路
   跨场景前置
   跨场景后续
   未定义引用项
   ```

## 11. 查询验收交付链路

1. 打开：

   ```text
   07_集群测试与验收交付.mmd
   ```

2. 优先确认以下主链路：

   ```text
   集群通信配置测试
   -> 集群系统集成测试
   -> 客户集群验收
   -> 输出验收报告
   -> 验收报告沟通
   -> 移交
   ```

3. 同时确认并列或相关活动：

   ```text
   计算管理系统对接
   网络管理系统对接
   存储管理系统对接
   线序及光链路质量排查
   综合布线整改
   集群性能调优
   ```

4. 注意：

   ```text
   集群性能调优依赖集群系统集成测试，但不是客户集群验收的直接前置。
   ```

## 12. 处理未定义引用项

1. 如果查询到 `远程视频辅助`，输出：

   ```text
   该项出现在“输出工勘报告”的 FS 依赖中，但不是正式活动行。
   ```

2. 如果查询到 `计算子系统验证-通算服务器`，输出：

   ```text
   该项出现在“集群通信配置测试”的 FS 依赖中，但不是正式活动行。
   ```

3. 不要继续查询其上游。

4. 不要补充工时和 SLA。

5. 不要把它改写为其他正式活动。

6. 如果用户要求修复，输出：

   ```text
   需要先在计划基线中补充正式活动行，再补充工时、SLA 和依赖关系。
   ```

## 13. 输出格式

1. 默认输出结构：

   ```text
   查询活动：xxx
   标准名称：xxx
   查询类型：前置依赖 / 后续影响 / 全量链路 / 开工条件 / 路径查询

   结果：
   1. xxx，依赖类型：FS，正式活动：是，来源：xxx.mmd
   2. xxx，依赖类型：SS，正式活动：是，来源：xxx.mmd
   3. xxx，依赖类型：FS，正式活动：否，说明：基线依赖引用，未定义活动行

   结论：
   xxx
   ```

2. 如果是多层链路，输出：

   ```text
   L1：
   - xxx -> xxx，FS

   L2：
   - xxx -> xxx，FS

   L3：
   - xxx -> xxx，FF
   ```

3. 如果用户要求 Mermaid，输出最小子图：

   ```mermaid
   flowchart LR
       A["上游活动"] -->|FS| B["目标活动"]
       B -->|FS| C["下游活动"]
   ```

4. 每次回答必须保留：

   ```text
   活动名称
   依赖类型
   正式活动判断
   来源文件
   ```

## 14. 禁止事项

1. 不要只用关键词搜索结果直接回答。

2. 不要忽略依赖类型。

3. 不要把 `FS`、`SS`、`FF` 混成普通先后关系。

4. 不要把未定义引用项当作正式活动。

5. 不要为未定义引用项推断上游依赖。

6. 不要在名称不唯一时直接猜测。

7. 不要只查场景图后就结束；跨场景或全量影响必须查 `00_活动总览-按一级活动.mmd`。

8. 不要输出没有来源的结论。

9. 不要修改 Mermaid 文件，除非用户明确要求更新基线或修正依赖。

## 15. 最小操作清单

1. 读取 `活动依赖映射0609.md`。

2. 标准化用户输入的活动名称。

3. 确认是否唯一命中活动。

4. 判断活动是否为正式活动。

5. 根据查询意图选择：

   ```text
   前置依赖
   后续影响
   全量上游
   全量下游
   两点路径
   场景链路
   开工条件
   ```

6. 查目标场景文件。

7. 查 `00_活动总览-按一级活动.mmd` 做全量确认。

8. 保留依赖类型。

9. 标记未定义引用项。

10. 输出来源文件。

11. 给出结论。
