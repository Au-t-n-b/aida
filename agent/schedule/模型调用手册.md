## 调用口径：默认流式 + 活性超时 + 有界重试（2026-06-14 指挥人定·全项目模型调用遵守）

> **背景**：T-026 收口实测 `qwen3.7-max` 生成结构化报告总结**单次约 44s**；非流式"死等"把"模型活没活"和"生成要多久"捆在同一个超时上——旧 30s 默认必被切断，而这 44s 里前端看不到任何反馈。改默认流式后二者解耦：首个模型增量很快到达即可作为活性信号，能马上判断有无反馈、没反馈快速重发。

**口径（实现见卡 T-040；落地前已有的非流式调用按本口径逐步迁移）**：

1. **默认流式**（`"stream": true`）：首个模型增量到达即"活性"确认。`qwen3.7-max` 可能先吐 `reasoning_content`、较晚才吐正文 `content`；活性判断认任意模型增量，最终结构化文本只累积 `choices[0].delta.content`。仅明确不需要早反馈的离线批处理（如基线风险精炼脚本）可用非流式。
2. **活性超时 ≠ 总超时（解耦）**：
   - **活性超时**短（建议 ~10s）：首 token 未在此窗口到达 = 判无反馈 → abort。
   - **总生成时间**长（建议 ≥90s）：只要 token 在持续流出就不算卡死，容忍 44s+ 的长生成。
3. **有界重试**：无反馈 / 可重试的瞬时失败（连接错误、空响应、活性超时）→ 重试 **N 次**（建议 2~3，指数退避）；耗尽仍失败才返明确错误码（`LLM_TIMEOUT` / `LLM_CALL_FAILED`）。
4. **结构化 JSON 输出**（如 `/report-summary`）：流式只买"活性 + 快速重试"——须**累积完整流后再解析**，**不能用半截 JSON**；前端契约可不变。**对话 / 叙述场景**才有"边吐边显"的渐进红利（v2 nanobot 对话 agent 复用本口径）。
5. **密钥 / 代理照旧**：只走 `.env` + 环境变量（§2）；本机 dashscope **直连即通**，经 env-var 代理时 httpx 可能 SSL EOF（T-026 实测，dashscope 直连不受 pip 那种指纹掐断影响）。

**实测基准**：`qwen3.7-max` 报告总结非流式 ~44s（2026-06-14，两次 43.4/44.0s）；T-040 流式真验收（2026-06-13，本机直连）首个模型增量 0.607s、首个正文 `content` 32.485s、完整流总耗时 39.418s，累积后可解析为 `ReportSummaryResponse`；极小活性超时触发 2 次尝试并返回 `LlmTimeoutError`。客户端默认总超时 90s（`BAILIAN_TIMEOUT_SECONDS` 可覆盖），默认活性超时 10s（`BAILIAN_LIVENESS_TIMEOUT_SECONDS` 可覆盖）。

## 一、百炼（阿里云 DashScope）

### 基本信息

| 字段 | 值 |
|------|-----|
| MaaS 平台 | 百炼 |
| API KEY ID | `5468874` |
| API KEY | `$BAILIAN_API_KEY`（见 `04 后端/.env`） |
| 协议 | OpenAI 兼容 |
| Base URL | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| Chat 端点 | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` |
| Models 列表 | `GET https://dashscope.aliyuncs.com/compatible-mode/v1/models` |

### 可用模型（6 个，均已实测）

| model 参数 | 说明 | 推荐场景 |
|-----------|------|---------|
| `qwen3.7-max` | 千问 3.7 旗舰 | 复杂推理、长任务（**本项目默认**） |
| `qwen3.7-plus` | 千问 3.7 增强 | 均衡性能与成本 |
| `qwen3.6-plus` | 千问 3.6 增强 | 日常对话、通用任务 |
| `glm-5.1` | GLM 最新（支持思考模式） | 推理、工具调用 |
| `glm-5` | GLM 旗舰 | 通用文本生成 |
| `glm-4.7` | GLM 上一代 | 轻量 GLM 任务 |

### 不可用模型（无需尝试）

- **VL 多模态**：`qwen-vl-max`、`qwen3-vl-plus`、`qwen2.5-vl-*`、`qvq-*` 等 → 403 无权限
- **GLM 视觉**：`glm-4.5v`、`glm-4.6v` 等 → 404/403
- **第三方代理**：`MiniMax-*`、`kimi-*`、`deepseek-*` → 403/404
- **旧版 Qwen**：`qwen-plus`、`qwen-max`、`qwen-turbo` → 403 无权限

### 调用示例

#### curl

```bash
curl -X POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions \
  -H "Authorization: Bearer $BAILIAN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.7-max",
    "messages": [{"role": "user", "content": "你好"}],
    "max_tokens": 1024
  }'
```

#### Python（OpenAI SDK）

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["BAILIAN_API_KEY"],   # 从 04 后端/.env 加载（python-dotenv）
    base_url=os.environ.get("BAILIAN_BASE_URL", "https://dashscope.aliyuncs.com/compatible-mode/v1"),
)

response = client.chat.completions.create(
    model="qwen3.7-max",
    messages=[{"role": "user", "content": "你好"}],
)
print(response.choices[0].message.content)
```

#### PowerShell（urllib 可能被防火墙拦截时用）

```powershell
$body = @{
    model = "glm-5.1"
    messages = @(@{ role = "user"; content = "你好" })
    max_tokens = 1024
} | ConvertTo-Json -Depth 5 -Compress

Invoke-RestMethod -Uri "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions" `
    -Method Post `
    -Headers @{
        "Authorization" = "Bearer $env:BAILIAN_API_KEY"
        "Content-Type" = "application/json"
    } `
    -Body $body
```

#### GLM 思考模式（可选参数）

```json
{
  "model": "glm-5.1",
  "messages": [{"role": "user", "content": "分析一下这个问题"}],
  "enable_thinking": true
}
```

## 四、通用请求格式

两套平台均兼容 OpenAI Chat Completions 格式：

```json
{
  "model": "<model参数>",
  "messages": [
    {"role": "system", "content": "你是一个有帮助的助手"},
    {"role": "user", "content": "用户输入"}
  ],
  "max_tokens": 2048,
  "temperature": 0.7,
  "stream": false
}
```

> 上为 OpenAI 通用格式参考（`stream` 缺省 false）。**本项目默认 `stream: true`**——见上「调用口径：默认流式 + 活性超时 + 有界重试」。

### 鉴权 Header

```
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

### 响应格式

取回复路径：`response.choices[0].message.content`

## 五、常见错误排查

| HTTP 状态 | 错误信息 | 原因 | 处理 |
|----------|---------|------|------|
| 401 | `Incorrect API key` / `Invalid authorization` | 密钥错误或密钥与端点不匹配 | 检查平台和端点是否对应 |
| 403 | `Model access denied` | 密钥有效但未开通该模型 | 换用本文档列出的可用模型 |
| 404 | `model_not_found` | model 参数名错误 | 对照本文档 model 参数表 |
| 超时 | 连接超时 | 网络/防火墙限制 | Windows 环境优先用 PowerShell `Invoke-RestMethod` |
