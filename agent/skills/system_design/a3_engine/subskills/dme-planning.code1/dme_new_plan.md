# DME 网络规划规则汇总（dme_new_plan）

> **优先级**：本文档为 DME 网络规划**主规范**；与 `dme-planning/SKILL.md` 及 `references/*` 冲突时，**以本文为准**。  
> 来源：产品规则（端口互联表 / 项目信息收集表 / 网络资源信息表）+ 原 Skill 中仍适用的条目。

| 网络平面 | DB `network_plane` | 接口名称 | Bond 模式 | VLAN | 节点 IP | 浮动/负载均衡 | 网关 | 目的网段 | 目的掩码 |
|----------|-------------------|----------|-----------|------|---------|--------------|------|----------|----------|
| DME 带外管理面 | `dme_oob` | **bond0** | 见 §2.6 | 网络资源信息表 | N | 见 §6 | 地址池第一个 IP | **0.0.0.0** | **0.0.0.0** |
| DME 带内管理面 | `dme_ib` | **bond1** | 见 §2.6 | 网络资源信息表 | N | 见 §6 | 地址池第一个 IP | **""** | **""** |

## 2. 共性规则

### 2.1 设备范围

| 项 | 规则 |
|----|------|
| 设备名称 | **计算带外管理面端口互联表**中的 **DME 设备** |
| DB 查询（规划输入） | `pro01_device_inventory`，`device_role LIKE '%DME%'`，`ORDER BY device_id` |

### 2.2 数据输入

| 数据项 | 来源表/字段 |
|--------|------------|
| 地址池 / 子网 | **网络资源信息表** → `ip_pool`（`dme_ib` / `dme_oob` / `dme_service`） |
| 掩码 | **项目信息收集表** → `mask` |
| VLAN | **网络资源信息表** → 按 **网络平面** 取 `vlan_pool` |
| 历史占用 | `occupied_ip`（格式与范围语法 **暂未确定**） |

### 2.3 IP 地址分配（节点 IP 与浮动 IP 共用）

从各平面地址池按序选取时，**必须排除**：

1. **网络地址**（子网号）
2. **广播地址**
3. **网关地址**（见 §2.4）

其余可分配主机地址按 `device_id` 顺序连续分配给节点；数据网络每节点 Port0、Port1 各 1 个。

### 2.4 网关

| 项 | 规则 |
|----|------|
| 计算公式 | 网关 = **地址池的第一个 IP**（该平面 `ip_pool` 对应子网的第一个 IP） |
| 与分配关系 | 网关 IP **不参与**节点/浮动 IP 分配（须排除） |

> 与原 Skill 中 `gateway_position` 字段关系：**暂未确定**是否仍读 DB；落地以「地址池第一个 IP」为准。

### 2.5 掩码

| 项 | 规则 |
|----|------|
| 来源 | **项目信息收集表** |
| 输出格式 | 节点 IP：`{IP}/{mask}` |

### 2.6 VLAN

| 项 | 规则 |
|----|------|
| 来源 | **网络资源信息表**中，与 **网络平面** 对应的 VLAN |
| 粒度 | **一台设备、一个平面、一个 VLAN**；同一设备不同平面、不同子网 → **不同 VLAN** |
| 带内 / 带外 | 平面有 VLAN 配置；接口名为 `bond0` / `bond1`（是否 `bondN.{vlan}` 子接口 **暂未确定**） |
| 数据网络 | 必须带 VLAN；接口名称为 **空** |

> **与旧 `constraint-rules.md` 差异**：旧规则写带内/带外「不应携带 VLAN TAG」；现网规则为每平面按网络资源信息表分配 VLAN，**以本文为准**。

### 2.7 Bond 模式（NCE / CCAE / DME 统一）

| 条件 | Bond 模式 |
|------|-----------|
| **有 MLAG** | **mode4** |
| **无 MLAG** | **mode1** |

| 平面 | 绑定方式 |
|------|----------|
| 带外 / 带内 | 2 网口跨网卡 Bond（带外 `bond0`，带内 `bond1`） |
| 数据网络 | **逐端口独立**，非 Bond |

MLAG 是否启用：来自项目/拓扑配置（**具体字段名暂未确定**）。

### 2.8 目的网段 / 目的掩码

| 平面类型 | 目的网段 | 目的掩码 |
|----------|----------|----------|
| **带外管理网络**（DME 带外 `dme_oob`） | `0.0.0.0` | `0.0.0.0` |
| **北向网络**（CCAE/NCE 体系中的北向平面；DME 无独立北向平面时不对应用） | `0.0.0.0` | `0.0.0.0` |
| **其余平面**（DME 带内 `dme_ib`、DME 数据 `dme_service`） | `""`（空字符串） | `""`（空字符串） |

DME 规划落表时：

- `dme_oob` → 输出 `0.0.0.0` / `0.0.0.0`
- `dme_ib`、`dme_service` → 输出 `""` / `""`

### 2.9 接口名称（bondN）

| 网络平面 | 接口名称 |
|----------|----------|
| DME **带外**管理面 | **bond0** |
| DME **带内**管理面 | **bond1** |
| DME **数据**网络（业务面） | **空**（不填 bond 名；端口级 Port0/Port1 见平面规则） |

## 3. 业务场景（三选一）

部署时 **DME 带外管理网络**、**DME 带内管理网络**、**DME 数据网络** 的组合仅下列三种（数据网络是否出现仍受 DataTurbo 约束）：

| 场景 ID | DME 带外管理面 | DME 带内管理面 | DME 数据网络 | 说明 |
|---------|---------------|---------------|-------------|------|
| **A** | ✓ | ✓ | ✓（DataTurbo） | 带外 + 带内 + 数据 |
| **B** | ✓ | —（空） | ✓ | 带外 + 数据 |
| **C** | —（空） | ✓ | ✓ | 带内 + 数据 |

- 「为空」= 该管理面 **不参与本集群规划**（无地址池或无互联表项）。
- 场景决定 **是否出现** `dme_ib` / `dme_oob` 行及 **浮动 IP 用途数量**（§6）。

## 6. 网络用途规划（浮动 IP / 负载均衡 IP）

划分逻辑取决于规划上下文中 **##DME 带外管理面##** 与 **##DME 带内管理面##** 是否为空（与 §3 场景一致）。

### 6.1 其中一个管理面为空（场景 B 或 C）

须规划 **3 个用途**，**全部从 DME 带外管理面地址池** 分配（遵守 §2.3 IP 排除规则）：

| 序号 | 用途名称 | 地址池 |
|------|----------|--------|
| 1 | 带外南向浮动 IP | 带外管理面 |
| 2 | 带外北向浮动 IP | 带外管理面 |
| 3 | 带外负载均衡 IP | 带外管理面 |

> **场景 C（仅带内 + 数据）**：规则文本仍写「从带外池」；若现场 **无带外地址池**，浮动 IP 池归属 **暂未确定**，实施前需与产品确认是否改为带内池或强制保留带外池。

### 6.2 两个管理面均不为空（场景 A）

须规划 **4 个用途**：

| 序号 | 用途名称 | 地址池 |
|------|----------|--------|
| 1 | 带外南向浮动 IP | 带外管理面 |
| 2 | 带外北向浮动 IP | 带外管理面 |
| 3 | 带外负载均衡 IP | 带外管理面 |
| 4 | 带内南向浮动 IP | **带内管理面** |

### 6.3 与旧 Skill 差异（以本文为准）

| 旧 Skill / output-template | 本文规则 |
|---------------------------|----------|
| 带内固定 3 个：北向、南向、**DME 负载均衡** | 带内仅 **南向** 浮动（且仅双管理面）；负载均衡归 **带外** |
| 带外仅南向；北向 **条件**（CCAE） | 带外固定含 **南向 + 北向 + 负载均衡**（3 或 4 用途组合） |
| 浮动 IP「系统自动选择、不分配真实 IP」 | 用途从指定 **地址池规划**（须排除网关等）；是否落具体 IP 表 **暂未确定** |

## 9. 规划执行顺序

```
1. 识别业务场景（§3）：带外/带内/数据 哪些平面非空
2. 取端口互联表中的 DME 设备列表 → N
3. 读网络资源信息表、项目信息收集表 → 各平面 ip_pool / mask / vlan
4. 各平面：计算网关（地址池第一个 IP）→ 排除网络/广播/网关后分配节点 IP
5. 按 §6 划分浮动/负载均衡用途并从对应地址池规划
6. 填写目的网段/掩码（§2.8）、接口名（§2.9）、Bond 模式（§2.7）
7. 校验：IP 唯一、池容量、Omni-dataverse≥3 节点等（原 Skill 仍适用部分）
8. 输出 Excel（dme-planning/output/）
```

## 10. 约束校验（更新后）

| # | 规则 |
|---|------|
| 1 | Omni-dataverse 启用 ⇒ N≥3 |
| 2 | 带内南向浮动 IP（若存在）与带内节点 IP 同网段、同池规则 |
| 3 | 全局 IP 不重复（含各池浮动用途） |
| 4 | VLAN 按网络资源信息表、**一设备一平面一 VLAN** |
| 5 | 带外 bond0 / 带内 bond1；数据面接口名为空；Bond：MLAG→mode4 否则 mode1 |
| 6 | 浮动用途数量：单管理面 3、双管理面 4（§6） |
| 7 | DataTurbo 与数据网络同现或同缺 |
| 8 | 目的网段/掩码：带外 `0.0.0.0`，其余 `""` |
| 9 | 分配时排除网络地址、广播地址、网关地址 |

| 项 | 说明 |

| 场景 C 无带外池时的浮动 IP 池 | 规则写从带外池，与「仅带内+数据」可能矛盾 |

| 浮动 IP 是否写入具体地址 | 仅用途划分 vs 落表分配 |
