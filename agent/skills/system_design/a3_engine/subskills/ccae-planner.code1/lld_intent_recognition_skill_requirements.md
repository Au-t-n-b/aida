# LLD 意图识别 Skill 改造需求说明

## 1. 业务目标

将当前 LLD 意图识别能力改造为一个阶段 Skill。

该 Skill 的核心目标是：识别用户自然语言输入中的 LLD 相关指令，并归一化为现有分类体系中的标准命令，方便后续模型根据识别结果调用对应的子 Skill。

## 2. 输入

Skill 只接收一个输入：

- 用户自然语言问题

示例：

- 生成LLD
- 交换机双活规划
- 帮我做网络规划
- 检查输入件有没有问题

## 3. 输出

Skill 对外永远只输出一段文本，不暴露内部状态机字段。

### 3.1 识别成功

当识别到单一明确命令时，直接输出标准命令字符串。

示例：

```text
交换机MLAG规划
```

### 3.2 需要追问

当用户输入存在多个合理候选，无法唯一确定意图时，输出一句追问话术。

示例：

```text
请问您要做地址规划、互联规划、接入规划还是路由规划？
```

### 3.3 识别失败

当无法找到任何合理分类时，输出固定失败话术。

建议固定话术：

```text
当前问题不属于LLD设计支持范围，请输入地址规划、互联规划、接入规划、LLD设计等相关指令。
```

## 4. 分类识别原则

### 4.1 沿用现有分类体系

继续沿用当前意图识别中的一级、二级、三级分类体系。

成功识别时，不要求必须落到三级分类。

只要用户输入能够精准匹配到一级、二级或三级指令，即可直接输出该级标准命令。

### 4.2 精准匹配优先

如果用户输入与现有分类词汇完全匹配，则直接输出对应标准命令。

示例：

```text
输入：交换机MLAG规划
输出：交换机MLAG规划
```

### 4.3 允许语义近似匹配

允许根据用户口语化表达、同义表达、业务近似表达识别标准命令。

但最终输出必须是分类词汇表中的标准名称，不能输出自造命令。

示例：

```text
输入：交换机双活规划
输出：交换机MLAG规划
```

```text
输入：出一份完整LLD
输出：生成完整LLD设计
```

### 4.4 单一高置信候选直接输出

如果语义近似匹配后只有一个高置信候选，则直接输出该标准命令。

### 4.5 多候选竞争时追问

如果用户输入可能对应多个合理分类，不硬猜，进入追问。

示例：

```text
输入：帮我做网络规划
输出：请问您要做地址规划、互联规划、接入规划还是路由规划？
```

## 5. 状态机设计

Skill 内部可以按状态机组织，但对外不输出状态字段。

### 5.1 状态定义

| State | 含义 |
| --- | --- |
| INIT | 接收用户自然语言问题 |
| CLASSIFYING | 执行精确匹配、别名匹配、语义近似匹配 |
| RESOLVED | 识别到单一明确命令 |
| CLARIFYING | 存在多个合理候选，需要用户补充 |
| FAILED | 无法找到合理分类 |

### 5.2 状态流转

```text
INIT
  -> CLASSIFYING
      -> RESOLVED     输出标准命令
      -> CLARIFYING   输出追问话术
      -> FAILED       输出固定失败话术
```

## 6. Action 设计

### INIT

动作：

- 接收用户自然语言问题
- 去除无关寒暄和弱动作词
- 保留关键业务动作词，例如“生成”“融合”“检查”“查询”

触发条件：

- 用户发起 LLD 相关或疑似相关请求

输出：

- 进入 `CLASSIFYING`

### CLASSIFYING

动作：

1. 执行标准分类词精准匹配
2. 执行业务别名匹配
3. 执行语义近似匹配
4. 判断候选结果数量和置信度

触发条件：

- 已获得用户自然语言问题

输出：

- 单一明确候选：进入 `RESOLVED`
- 多个合理候选：进入 `CLARIFYING`
- 无合理候选：进入 `FAILED`

### RESOLVED

动作：

- 输出标准命令字符串

触发条件：

- 精准匹配到一级、二级或三级命令
- 或语义近似匹配得到单一高置信候选

输出：

```text
标准命令
```

### CLARIFYING

动作：

- 基于候选分类生成一句追问话术

触发条件：

- 用户输入过宽泛
- 存在多个合理候选
- 无法唯一确定标准命令

输出：

```text
追问话术
```

### FAILED

动作：

- 输出固定失败话术

触发条件：

- 无法找到任何合理分类

输出：

```text
当前问题不属于LLD设计支持范围，请输入地址规划、互联规划、接入规划、LLD设计等相关指令。
```

## 7. 后续 Skill 文件建议

建议将 Skill 拆分为以下结构：

```text
lld-intent-recognition/
├── SKILL.md
├── intent-taxonomy.md
├── intent-aliases.md
└── intent-examples.md
```

### SKILL.md

放置核心执行规范：

- Skill 业务目标
- 输入输出约束
- 状态机
- 匹配优先级
- 追问和失败规则

### intent-taxonomy.md

放置一级、二级、三级分类树。

用于保证输出命令必须来自标准分类体系。

### intent-aliases.md

放置业务别名、同义词、口语表达映射。

示例：

```text
交换机双活规划 -> 交换机MLAG规划
出一份完整LLD -> 生成完整LLD设计
检查输入表 -> 检查输入件是否妥当
```

### intent-examples.md

放置典型输入输出样例，包括：

- 精准匹配样例
- 语义近似匹配样例
- 多候选追问样例
- 失败样例

## 8. 改造目标总结

改造后的意图识别 Skill 应满足：

- 能识别用户自然语言中的 LLD 业务指令
- 能输出现有分类体系中的标准命令
- 不强制识别到三级分类
- 支持语义近似匹配
- 多候选竞争时主动追问
- 无合理分类时输出固定失败话术
- 对外输出保持极简，只输出一段文本
