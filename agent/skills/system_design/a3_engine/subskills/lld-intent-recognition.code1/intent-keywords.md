# LLD 意图关键词映射

用户输入**未完整说出标准命令**时，通过身份关键词子集匹配归一化。匹配时大小写不敏感。

## 归一化（关键词匹配前）

1. 去除寒暄：`帮我`、`请`、`让我们执行`、`做`、`执行`
2. 动作词剥离（与 SKILL 一致）：`生成`、`融合`、`检查`、`查询`、`替换` 作为前缀时可剥离；`生成LLD` 除外
3. 忽略可选尾缀：`规划`、`设计`、`表`、`文件`、`方案`
4. 同义归一：
   - `XX面`（无「地址/互联/接入」后缀时）保留为平面标识
   - `IP规划`、`网段规划`、`IP地址` → 含 `地址` 语义
   - `双活`、`堆叠`、`跨框聚合` → `MLAG`
   - `零配置开局` → `ZTP`
   - `校验`、`检查` → 含 `检查` 语义
   - `进度`、`设计进度` → 含 `进度` 语义
   - `设备清单`、`清单` → 含 `设备清单` 语义
   - `改设备名`、`重命名` → 含 `替换设备名称` 语义

## 匹配规则

1. 对 [intent-taxonomy.md](./intent-taxonomy.md) 中**每一条**标准命令，按下表「身份关键词」在归一化后的用户输入中做**全包含**检测（每个关键词均须出现，顺序不限）。
2. 身份关键词中的 `{可选}` 表示用户可不写该词；未标注 `{可选}` 的为必选。
3. 命中多条时取**关键词总数最多**（最具体）的命令；若最多关键词数仍有多条并列 → 进入 CLARIFYING，列出并列候选。
4. 仅当命中**唯一**最具体命令时 → RESOLVED。
5. 关键词匹配**不**自造命令；输出必须来自 taxonomy。

## 规划类型缺省时的消歧

| 用户输入特征 | 处理方式 |
| --- | --- |
| 含 `互联` 或 `互联规划` | 仅匹配互联规划族 |
| 含 `接入` 或 `接入规划` | 仅匹配接入规划族 |
| 含 `地址`、`IP`、`网段` 或未出现互联/接入 | 优先匹配地址规划族 |
| 同时命中地址/互联/接入同级候选 | CLARIFYING，列出候选 |
