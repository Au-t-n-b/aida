# 交付预案 §3.3.2 输出结果 — Excel 提取结果 · 缺失与 AI 构造说明

## 这是什么
本目录是从样例预案页面 `http://localhost:5174/proposal`（数据源 `proposal-data.ts`）按两份指引文档提取的 **§3.3.2 输出结果**，每张表导出为一个独立 `.xlsx`，共 **22 个文件**。

- 指引①：`05-数据目录与平台规范.md` §3.3.2 / §4.2 —— 定义有哪些输出表。
- 指引②：`04-预案上下文-全量与决策.md` —— 定义每张表的字段。
- 生成脚本：`../gen_proposal_excel.py`（可重跑复现）。

> **数据真伪标注原则**：凡样例页面已有的数据＝**真实提取**；样例中缺失、由 AI 补的＝**AI 构造**，下文逐项列出，且在对应 Excel 的**表头**用「(AI构造)」标注、或在本文件登记。

## AI 构造明细（逐项可追溯）

### A. 项目身份字段 —— 样例 `proposal-data.ts` 无对应来源
| 字段 | AI 构造值 | 出现于 | 说明 |
|---|---|---|---|
| 项目ID | `PRJ-JD3-2026-001` | 01、02 | 样例只有机会点编码，无项目ID |
| 项目编码 | `K1903-JD-AIDC-2026` | 01、03 | 样例只有机会点编码 `K1903`，无独立项目编码 |
| Proposal号 | `PROP-2026-K1903-001` | 01 | 样例无该字段 |
| 项目名称 | `京东三期项目` | 01、02、03 | **半构造**：由样例 `oppName=京东三期` + 文档标题推得 |

> 说明：按 `04` §2，「项目基础信息表」本是**合同模块上游、预案只读**；样例预案页未投影这些身份字段，故此处由 AI 补齐以保证 Excel 完整。真实落地时应取自合同侧 `项目基础信息表`。

### B. 服务内容「单位」列（14_服务内容表.xlsx 整列 AI 构造）
`04` §13.2 要求列含「单位」，但样例 `SERVICE_CONTENT_TREE` 无 `unit` 字段。AI 按内容关键字规则构造：

| 规则（内容含…） | 单位 |
|---|---|
| 一级（蓝行 offering） | 套 |
| 含「单板」 | 单板 |
| 含「项目经理/技术经理/文档督导」 | 人次 |
| 含「物理安装/台架安装」 | 台 |
| 含「标签制作」 | 处 |
| 含「光纤熔接」 | 芯 |
| 其它 | 次 |

> 仅「单位」列为构造；服务名称/服务内容/数量/来源均真实提取。

### C. 测试用例表（19_测试用例表.xlsx，6 列 AI 构造）
样例 `TEST_CASE_GROUPS` 只有**一级「测试类型」+ 用例名称**；详情 `TEST_CASE_DETAIL_TEMPLATE` 为**所有用例共用一套模板**（link-delay 演示数据），无逐用例真实数据。AI 按 `04` §17 要素构造：

| 列 | 真/构造 | 构造方式 |
|---|---|---|
| 一级分类 | AI 构造 | 统一取 `A3超节点验收测试（液冷场景）`（源自 `04` 提到的上传用例文件名） |
| 二级分类 | AI 构造 | 按测试类型映射子系统（硬件/网络/计算 + 细分） |
| 三级分类 | **真实** | = 样例原「测试类型」 |
| 用例编号 | AI 构造 | `TC-{类型缩写}-{序号}`，如 `TC-OPT-001` |
| 用例名称 | **真实** | 样例原用例名 |
| 测试目的 | AI 构造 | 模板：「验证{用例名}在 A3 超节点液冷场景下的功能/指标满足验收要求。」 |
| 测试组网 | AI 构造 | 统一通用组网描述（DUT1/DUT2 直连 + 网管接入） |
| 预置条件 | AI 构造 | 统一通用预置条件（上电/版本/链路） |
| 测试步骤 | AI 构造 | 统一通用 4 步（检查→执行→采集→比对） |

> ⚠ 测试用例的「测试目的/组网/预置条件/步骤」为**通用占位构造**，非逐用例真实测试规程。真实落地需「A3超节点验收测试用例-液冷场景.doc」多模态解析结果。

### D. 共平面类型表（08，表形态构造）
样例为 5.1 顶部多选控件（默认四面全选），未持久化为表。AI 将其整理为独立表：四行「带外管理面/带内管理面/业务面/样本面 + 是否选中 + 预案版本号」。**值真实**（默认全选、版本号=默认快照 `V3.1_20260604173100`），仅「成表」这一形态为构造。

## 未构造、保持原样的部分（重要）
- **07_网络平面配置信息表**：样例有 10 个设备角色，其中 7 行为**空占位**（型号/数量空、备注「HLD 待补」）。这些是样例**有意留空的待补行**，并非确定性缺失数据，AI **未编造**交换机型号/数量，保持空白以免污染。如需补全须依据真实 HLD。

## 不计入 §4.2 输出表的两张（已导出但标注）
- **21_风险列表 / 22_假设表**：`04` §18 明确风险与假设**不属交付预案输出章节**，落「项目管理/风险·假设」，预案只读引用。因样例数据存在，一并导出，但**不算 §3.3.2 的预案输出表**。
