# A3超节点集合通信算子性能测试本体建模与Markdown数据

## 一、核心实体与定义
| 实体名称 | 定义 | 关键属性 |
| :--- | :--- | :--- |
| **算子** | 本次测试的分布式集合通信操作类型 | 名称：`allreduce`、`alltoall`、`alltoallv`、`scatter`、`reduce_scatter`、`all_gather`、`reduce`、`broadcast` |
| **节点数** | 参与通信测试的计算节点数量，部分多节点场景按POD（集群单元）划分 | 取值：`2,4,8,16,32,48,96(2POD),144(3POD),192(4POD),240(5POD)`；其中POD为集群物理单元，`N POD`对应节点数=48×N |
| **数据量** | 单次通信操作传输的数据规模，为测试的变量维度 | 取值：`1G,2G,4G,8G,16G`（单位：GB） |
| **性能指标值** | 对应算子+节点数+数据量组合下的通信性能表现值（数值越高代表性能越优） | 浮点型数值，精度保留2位小数 |

---

## 二、实体关系与语义约束
1.  **多对多映射关系**：每个`算子`与`节点数`、`数据量`构成三维测试组合，每个组合对应唯一的`性能指标值`。
2.  **节点数逻辑约束**：
    - 节点数≤48：属于单POD内节点规模；
    - 节点数≥96：按`N POD`划分，节点数=48×N（如96=48×2、144=48×3，以此类推），表示跨POD的节点规模。
3.  **性能趋势约束**：
    - 同算子、同数据量下，性能指标值随节点数增加整体呈下降趋势（节点数越多，通信开销越大，性能衰减越明显）；
    - 同算子、同节点数下，数据量从1G提升至2G时，性能指标值通常有明显提升，4G及以上数据量下性能指标值趋于稳定，无显著波动；
    - 跨POD场景（节点数≥96）的性能指标值普遍低于单POD场景，部分算子（如`alltoall`）跨多POD时性能衰减极为显著。

## 四、补充语义说明
1.  **性能衰减差异**：跨POD场景下，`alltoall`/`alltoallv`的性能衰减最为剧烈，144节点（3POD）时性能指标值已降至个位数；`reduce`在单POD内（≤48节点）的性能随节点数增加显著下降，跨POD后反而回升并保持稳定。
2.  **数据量影响**：大部分算子在数据量≥4G时，同节点数下的性能波动均小于±1，说明大数据量下通信性能趋于稳定；部分算子（如`reduce_scatter`）在数据量从1G提升至2G时性能提升超过20%。
3.  **算子特性约束**：`all_gather`在低节点数（≤16）时性能指标值显著高于其他算子，属于带宽敏感型通信操作；`reduce`在32/48节点时性能指标值远低于其他算子，属于计算与通信耦合度较高的操作。
