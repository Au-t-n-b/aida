# 预案数据来源分类与缺失清单

> 基于 `预案的初步的来源信息.md` 与当前 `预案schema` 整理。本文只描述数据来源、当前本体承载关系和缺失项，不生成实例数据，不修改 schema metadata。

## 1. 总览

当前预案来源可分为 5 类：

| 分类 | 说明 | 当前处理方式 |
| --- | --- | --- |
| 原始文件 | 合同文件、BOQ、HLD、服务建议书、维保建议书等输入文件 | 作为 `EvidenceSource` / `ConfigurationFile` 的证据来源，解析后写入业务对象 |
| 解析结果 | 项目交付特点、HLD 解析、服务建议书解析、维保建议书解析、设备信息表等 | 解析结果实例进入配置、服务、维保、风险、假设等本体对象 |
| 结构化数据库表 | 项目、预案版本、设备、软件、网络、服务、责任矩阵、验收、风险、假设等逻辑表 | 与当前 24 个 ObjectType 大体对齐，部分字段暂未建模 |
| 外部系统/接口 | 机会点接口、产品生命周期接口、CAD/工勘/HRD、风险接口、数据湖、计划模块、模板库 | 作为上游数据源或计算输入，当前只在本体中保留结果对象 |
| 派生/计算结果 | 总空间、总功耗、冲突说明、交付评估结论、Gap、整改任务 | 由解析和评估逻辑生成，进入评估、Gap、任务、风险等流程对象 |

当前结论：

- 当前删减版 JD 预案样例可以由现有预案本体生成。
- 完整来源血缘仍缺真实文件指针、解析结果实例、部分数据库字段和计划活动明细。
- 合同信息继续只作为证据来源，不作为独立业务对象进入预案本体。
- 交付方案在来源文件中标注为“暂不”，当前不纳入预案生成范围。

## 2. 数据来源分类

### 2.1 原始文件类

| 来源域 | 来源项 | 来源形态 | 可生成内容 | 当前处理 |
| --- | --- | --- | --- | --- |
| 合同 | 合同文件 | file / contract / 本期 | 交付边界、验收约束、回款依据、合同风险线索 | 作为证据来源，不建合同业务对象 |
| 合同 | BOQ | file / contract / 本期 | 设备、部件、软件、服务、维保、数量 | 作为证据来源，解析后进入配置与服务对象 |
| 交付预案 | HLD | file / proposal / 本期 | 项目背景、组网、软件版本、集成验证需求 | 作为证据来源，解析后进入需求、网络、软件、集成验证对象 |
| 交付预案 | 服务建议书 | file / proposal / 本期 | 服务交付界面、服务内容 | 解析后进入 `ServiceConfig` |
| 交付预案 | 维保建议书 | file / proposal / 本期 | 维保策略、SLA | 解析后进入 `MaintenancePolicy`、`SlaRequirement` |

## 4. 当前无法直接获取或无法完整生成的内容

| 缺失内容 | 缺失原因 | 建议处理 |
| --- | --- | --- |
| 原始文件正文 | 当前来源文件只列目录和类型，没有文件内容 | 后续通过 `ConfigurationFile.storageUri` 指向真实文件 |
| 真实文件指针 | 当前没有实际 `storageUri`、`versionHash`、文件清单 | 补充文件资产实例，保留冷热分离 |
| 解析结果实例 | 只知道 HLD解析结果、服务建议书解析结果等目录，没有解析后的 JSON/表记录 | 补充解析结果实例数据或落表结果 |
| 合同金额、签署方、签署日期 | 当前本体明确不建模合同业务对象 | 仅作为证据来源；如生成合同章节需单独调整边界 |
| 项目ID、项目编码、Proposal号 | 来源表存在，但当前删减版 JD 样例不需要，现有本体未完整承载 | 如恢复项目标识展示，可补充到 `ProjectRequirement` 或 `ContingencyPlan` |
| 创建人、文档摘要、本次修改记录、完整修改记录 | 来源表存在，但当前本体仅保留版本、更新人、更新时间和来源摘要 | 如需要版本审计，可补充版本历史对象或字段 |
| 设备厂家、产品编码、设备数据来源 | 来源表存在，当前删减样例已收窄，`EquipmentConfig` 未完整承载 | 如要还原全量设备表，可补充 `vendor`、`productCode`、`dataSource` |
| 风险领域、产品域、计划关闭日期 | 来源表存在，当前 `RiskItem` 只保留生成样例所需核心字段 | 如要还原风险管理表，可补充风险域字段 |
| 假设闭环状态细节 | 当前 `AssumptionItem.status` 可承载状态，但没有专门闭环字段 | 当前够生成样例；完整闭环可补字段 |
| 计划活动明细 | 当前只有 `PlanScheduleSnapshot` 摘要，没有活动级计划对象 | 若恢复活动明细，需要新增计划活动对象或引用计划模块数据 |
| 交付方案输入/解析/输出 | 来源文件标注为“暂不” | 当前不纳入预案本体和文档生成 |
| 代码资产来源 | 当前来源分类没有代码资产输入 | 不作为当前预案本体对象 |

## 5. 建议处理原则

1. 合同信息继续不建业务对象，只通过 `EvidenceSource` / `ConfigurationFile` 表达来源和证据。
2. 当前 JD 样例生成优先使用已有 24 个 ObjectType，不为删减版样例新增对象。
3. 原始文件、解析结果和输出文件采用文件指针方式承载，避免把文件正文放入本体层。
4. 完整血缘建设优先补实例数据：真实文件指针、解析结果实例、数据库表记录和计划模块输出。
5. 仅当要恢复全量设备表、风险管理表、计划活动明细时，再考虑补字段或新增计划活动对象。
6. 章节、字段和文档映射属于上层模板或 Agent 编排，不进入底层业务本体。

## 6. 结论

当前本体足够支撑删减后的预案文档生成。`ProjectRequirement`、`EquipmentConfig`、`ComponentConfig`、`SoftwareConfig`、`NetworkConfig`、`MachineRoomConfig`、`ServiceConfig`、`MaintenancePolicy`、`SlaRequirement`、`ResponsibilityMatrixItem`、`IntegrationVerificationRequirement`、`AcceptanceStrategy`、`RiskItem`、`AssumptionItem` 和 `PlanScheduleSnapshot` 已覆盖主要业务章节。

若要覆盖完整来源信息，重点不是恢复文档排版对象，而是补齐三类数据：真实文件指针、解析结果实例、以及当前未进入删减版样例的表字段。交付方案仍按来源文件标注暂不纳入。
